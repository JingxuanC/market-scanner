# market-scanner

A 股个人量化工作台：**选股 → 下单清单 → 记账归因**，架在现有 hub MCP
（数据 / 因子 / ML / kronos / 事件研究 / 因果记忆）之上。

设计全文见 [`DESIGN.md`](DESIGN.md)。适用对象：全职盯盘、**手动下单**的个人投资者。

## 三条轨（互相独立记账，绝不混在一起看总收益）

| 轨 | 做什么 | 依赖 | 节奏 |
|---|---|---|---|
| **日频轨** | 可交易域 → h5 读行情 → 因子 → ML 打分 → 组合优化 → 候选池 | 共享磁盘（h5/qlib 只读）+ hub MCP | 20:10 |
| **执行层** | 候选池 + 持仓 → 差额 → **照着点就能下的清单** | 日频轨产出 | 14:35 |
| **盘中轨** | 全市场快照 delta → **只告警持仓 ∪ 候选池** | hub MCP | 5 分钟 |
| **记账轨** | `record_decision` → T+1/5/10/20 回填 → 周日分层报告 | 因果记忆 | 15:10 + 周日 |

## 与 athena 的关系（重要，别搞混）

两者**共用同一个因子源**：factor-miner 20:00 cron 写 Redis `dfactor:{symbol}`，
athena 的 `internal/factor/cache.go` 直接读它喂给 WarRoom。market-scanner 是
**同一因子层的第二个消费者**，用不同方法（因子→ML→组合优化→权重→清单）对上
athena 的 WarRoom（7 战法 + LLM 辩论 → Top5 等权）。

**结论：独立成仓。** 原因是设计 §4.4 本来就是在批评 Top5 等权那个做法——
两个方法要能被公平对比，就必须各自独立、各自记账（§9 的分层度量依赖干净归因）。
塞进 athena 会把"要不要换方法"这个决定和旧方法的代码缠在一起。

## 铁律（写进代码前先读）

1. **不下单**。产出是人能照着点的清单；将来若接自动下单，**首次交易前必须先做程序化交易报告**。
2. **绝不提交个人持仓/资金**。`positions.json` 在 `.gitignore` 里，只存在于运行环境。
3. **不静默降级**。数据源退化、覆盖面不足、模型缺失——一律显式报错并保留旧数据，
   绝不用"看起来像那么回事"的结果继续跑（2026-09 hub 数据事故的教训）。
4. **单源必挂**。免费行情源会 502、会截断、会限流；任何"全市场"结论都必须双源可交叉。
